# 官方专家与知识召回完整方案

日期：2026-11-09。状态：方案建议，尚未实施、迁移或部署。

## 1. 目标与范围

在现有猛犸系统内实现与 Monica 专家功能和操作流程对齐的系统：超级管理员配置专家，普通用户从广场使用。知识入库、chunk 切分、索引、连续会话召回和真实出处是第一优先级。复用 Vue 管理端、NestJS 中台、Prisma/PostgreSQL 和 mammoth-agent Harness。

本方案自行定义检索实现。Monica 的客户端及随包源码能够证明独立的知识处理、embedding 失败状态和 search_knowledge 协议，但不能证明其服务端切块参数、向量模型、存储、召回数量、重排或每轮检索策略；以下参数均为本系统的建议初始配置。

用户已明确：第一期仅超级管理员创建、修改、发布官方专家。企业和个人自建专家、专家交易市场、多人协作编辑暂不进入第一期。用户使用专家的可见性沿用现有产品授权规则，不能把“只有超管能编辑”误实现成“只有超管能使用”。

完整交付分为 V1 和 V1.1：V1 包含文本 RAG、专家配置、内置工具、真实预览、发布与回退；V1.1 增加 OpenAPI 外部工具、OCR 和复杂文档专项处理。V1 不能宣传为支持尚未完成的 V1.1 功能。

## 2. 实施路线

| 路线 | 适用情况 | 代价 |
|---|---|---|
| 推荐：在现有系统中增加统一知识服务和版本化专家执行配置 | 复用已有登录、租户、计费、模型池及客户端 | 需要为现有三套资料路径增加兼容层和迁移校验 |
| 独立部署一个完整的外部 RAG 产品，再对接专家 | 团队已经运维相应产品且希望由它承担知识运营 | 增加账号、权限、版本、计费和故障处理的跨系统同步 |

本方案按第一条路线展开，这是方案作者的建议，不代表已获准实施。初期保留 PostgreSQL 与 pgvector，原文件通过现有存储抽象保存；检索质量和容量测试证明需要独立服务时，再拆分检索部署。

## 3. 产品对象与职责

| 对象 | 职责 |
|---|---|
| 专家 | 角色、指令、流程、输出要求、推荐提问、模型策略和能力关联 |
| 知识库 | 可被多位专家复用的资料集合，有独立的资料发布版本 |
| 文档及文档版本 | 保存原文件、文件哈希、解析结果和真实定位信息；替换只追加版本 |
| 索引版本 | 记录解析器、切块方式、Embedding 模型及维度；与原文版本一起可追溯 |
| 方法技能 | SKILL.md 及资源包，说明怎样完成任务；不因此授予工具权限 |
| 工具 | 真正执行搜索、计算、文件操作或外部 API 的能力 |
| 专家发布版本 | 冻结一套可执行配置，并指向确定的知识发布和技能包版本 |
| 检索记录 | 保存本轮召回的来源、排名、使用范围、耗时和成本信息 |

专家配置和知识内容独立存储。知识库不再必须在仓库资产中预声明，也不因专家是 GENERAL 类型而禁止绑定。旧类型可保留为兼容字段，实际能力由配置和权限决定。

## 4. 用户操作流程

### 超级管理员后台

1. 在知识库管理创建资料集合，上传文件，查看解析、切块、向量化和索引状态。
2. 预览抽取文本和 chunk，核对页码、标题及表格是否正确；失败项可重试。
3. 在检索测试区输入问题，查看候选片段、排序和出处；支持先测检索、不调用回答模型。
4. 创建或编辑专家：基本信息、专家指令、知识库、方法技能、工具和模型策略分别维护。
5. 在草稿预览中提问，查看本轮是否检索、用了哪些片段、调用了哪些工具及实际用量。
6. 通过发布检查后发布；列表明确区分草稿修改与当前线上版本。
7. 可比较发布版本、回退配置或下架专家。回退发布新版本并引用原快照，保留审计历史。

### 用户网页与客户端

从专家广场进入，新会话固定到一个专家发布版本。发送问题后展示查找资料、生成回答等真实状态；回答中的引用可打开对应文档版本的原文位置。后续追问在同一会话内处理指代和上下文。无依据、检索故障、无权限及不支持的文件状态必须分别说明。

网页与客户端使用同一套 Ground 知识检索接口。客户端本机文件、终端等能力由 Harness 原有权限机制管理；后台单独展示“本机能力”和“云端工具”，不把云端工具勾选项描述为全部实际能力。此处保留本机能力是方案建议。

## 5. 模块架构

资料准备链：上传入口 → 原文件存储 → 文档版本 → 后台任务 → 文本与结构提取 → chunk → Embedding → 关键词及向量索引 → 校验 → 发布知识版本。

会话回答链：用户问题与必要上下文 → 核验账号及专家版本 → 计算授权资料范围 → 构造检索问题 → 双路召回 → 合并、去重、重排 → 组装证据 → 模型回答 → 引用校验与展示。

Ground 负责知识、索引、权限、云端模型与工具凭证、检索和用量。Harness 负责会话、模型输入组装、本机能力以及工具执行过程呈现。索引 Worker 在独立进程运行，复用中台代码和数据库任务表；请求进程不等待长文档完成索引。第一期不强制增加 Redis 或新的向量数据库。

建议在 Ground 增加统一 knowledge-core 服务，各资料来源通过适配器接入；新增代码不继续复制当前三套不同的切块与问答逻辑。对现有企业资料库的权限、文件版本、回收站和引用入口优先复用，不以统一索引为由改变这些规则。

## 6. 文件入库与处理状态

文件原始字节保留在存储层；数据库保存元数据、文本、chunk 和索引信息。业务只保存 storageKey，不绑定具体文件系统路径。沿用可持久化的现有上传存储，增加备份与存储适配接口；对象存储可后续替换而不改变业务 ID。索引 Worker 必须能读取同一份持久化存储。

第一期支持 Markdown、TXT、可提取文字的 PDF、DOCX、CSV。PDF 保留真实页码；DOCX/Markdown 保留标题层级和段落；CSV 按记录组切分并携带列名。扫描 PDF、图片、视频、老 Office、XLSX 和 PPTX 的专项理解在 V1.1 完成前明确标注“仅保存/下载或待转换”，不显示成可检索。

处理状态：已接收 → 解析中 → 切块中 → 向量化中 → 建索引中 → 可用。另有失败、取消、部分解析状态；错误附阶段和可操作原因。上传进度 100% 仅代表上传完成。解析成功、切块成功和向量索引成功不能合并为一个成功状态。

任务按文件版本、索引配置和内容哈希幂等。通过数据库任务租约领取、心跳和失败恢复避免重复执行；瞬时上游故障最多自动重试三次并退避，文件损坏等永久错误直接提示。取消后迟到结果不能把任务改回成功。中断可重试；未通过校验的索引不得切换为线上版本。

沿用现有 20MB 单文件上限作为初始限制；页数、提取量、单次索引成本等上限另由配置控制。不得静默截取长文档后仍称已完整入库。受限文档进入部分解析状态，并显示覆盖范围；第一期不允许部分解析资料进入默认“完整知识库”发布。

## 7. chunk 策略

按标题、段落、条款、列表和表格结构优先切分，超长部分再按句子拆开。每块携带标题路径、原文位置和相邻块关系。表格块重复表头，保留行号或页码；精确计算交给表格工具，不让文字检索代替计算。

初始调参值：目标约 600 tokens、最大约 900 tokens、相邻重叠约 80 tokens；按 Embedding 模型对应的 tokenizer 计算，不将字符数当 token。短章节可合并，表格和条款边界优先于目标长度。标题及附加元数据也必须计入模型输入上限。参数随评测集调整并生成新的索引版本。

检索命中小块后，按需要补充同一授权文档版本的前后片段或父级段落。不得跨文档拼接，不因补充上下文突破权限或模型预算。召回上下文默认预算不超过约 8,000 tokens，且服从所选模型总上下文及回答预留空间。

chunk 至少保存：库 ID、文档 ID、文档版本、索引版本、块 ID、序号、正文、标题路径、页码/段落/行号、起止位置、token 数、内容哈希。向量另保存 Embedding 配置版本、维度和块 ID；同一索引内不得混用模型或维度。

## 8. Embedding 与模型管理

对话模型、Embedding 模型、重排模型分别配置和健康检查，不假设现有可聊天模型同时提供另外两类能力。扩展现有超管模型管理的任务类型及适配层；所有密钥保留在 Ground 的凭证管理中，不传浏览器或客户端。

生产供应商和模型在接入阶段，根据当前账号可用服务、中文评测结果、延迟、价格及数据处理要求选择；不将某个新服务的账号或额度当作已具备条件。可用 BGE-M3 等多语言模型作为评测候选，不能把候选名称当作已确定部署方案。

文档向量和查询向量必须使用相同的 Embedding 配置。切换模型时后台重建新索引并比较结果，通过后发布新知识版本；不能将新查询向量直接与旧模型向量比较。相同内容和索引配置可在权限范围内复用结果，避免重复采购；每条向量保留来源和计量信息。

数据库继续使用 PostgreSQL + pgvector。新语义向量使用新索引存储，不覆盖旧 64 维字符哈希数据。小规模授权语料优先精确向量搜索，建立评测基线；规模增大后再测试 HNSW。近似索引与权限过滤组合时必须检查候选不足，必要时扩大受控扫描或回到授权范围内的精确搜索，不能扩大资料权限。[pgvector 检索与过滤说明](https://github.com/pgvector/pgvector#filtering)

## 9. 会话召回策略

### 检索范围

本轮范围由服务端计算：专家发布版本绑定的知识版本，加上用户本轮明确选择的资料，再与当前账号及租户可读权限取交集。第一期用户选资料可沿用已有企业资料库引用能力；如只发送普通本机附件，先走现有附件处理，不自动上传为永久知识库。

官方库使用明确的平台范围标记，不伪造企业 tenantId；企业资料始终带真实 tenantId。所有候选查询、补充片段、引用打开和缓存命中均受同一范围约束。模型不能通过传入任意知识库 ID 扩权。

### 提问与连续追问

保留用户原始问题。需要时结合本会话最近若干轮和必要摘要，生成独立可检索的问题，解决“它、这个条件、刚才那种情况”等指代。问题改写不得引入其它会话事实，也不得改变授权资料范围。对比问题可拆成最多三个子查询，检索后再合并。

### 两路召回和重排

建议初始流程：语义向量候选最多 40 块；中文关键词、专有名称、编号、日期及精确短语候选最多 30 块；两路在授权范围内执行。中文关键词需要分词及专有名处理，不能直接把默认英文分词当作中文检索；现有 trgm 可保留为字面短词补充。

合并去重后采用排名融合，避免把不同量纲的分数直接相加。重排前取最多 20 块，由独立 Rerank 模型重新判断相关性，默认选 6 块，再做来源多样性、相邻上下文补充和 token 预算裁剪。查询嵌入、候选数量、重排耗时均有上限。

相关性阈值以评测集标定，不预设一个对所有模型通用的分数。检索服务故障与“没有相关资料”使用不同结果状态；无证据时不强行生成资料性结论。重排故障可按预设策略降级到融合排名，并记录状态。[混合检索与排名融合](https://github.com/pgvector/pgvector#hybrid-search)、[BGE 检索与重排说明](https://huggingface.co/BAAI/bge-m3)

### 什么时候检索

超管选择“先查资料再回答”“按需查资料”或“关闭知识库”。有绑定知识库的资料答疑专家默认先查再答，由运行时保证在生成事实性回答前进行检索，不仅在提示词中写“必须检索”。通用专家可按需使用；模型需要补充证据时每轮最多追加一次检索。调用预算和循环上限统一控制。

没有证据时显示“未在当前可用资料中找到依据”；权限不足、文件未就绪和服务故障不冒充这个结果。允许通用知识补充时必须明确区分其来源；严格资料答疑模式只给有证据的结论。

## 10. 证据进入模型与引用

检索必须进入当前轮最终模型请求，而不是只在界面显示命中，或到下一轮才加载。Harness 使用模型输入组装阶段接入证据，记录实际进入模型的片段、版本、顺序和裁剪信息，遵守现有模型可见输入可从会话日志重建的规则。

以来源编号组织证据，例如 [S1]，每条对应确定的 chunk 和文档版本。知识正文始终作为不可信资料处理；其中的角色设定、提示词或命令不能改变系统权限。专家指令、方法技能与知识正文分开组装。

引用绑定文件、版本、块和真实定位；无页码来源不编造页码。打开引用时重新校验权限，默认返回精确版本的原文位置；不能默默跳到新版本。引用编号存在不代表结论已经被支持，验收同时检查“引用能打开”和“引用确实支持该句”。

会话压缩和恢复保留证据引用与必要正文重建信息。再次读取前重新授权；权限撤销不允许重新取回或发送资料，但不能声称能撤回此前已发送给模型的内容。

## 11. 发布、预览和版本

专家发布快照包含：指令和结构化流程、模型选择策略、方法技能包版本、云端工具版本、本机能力策略说明、知识库发布版本、检索模式和参数配置版本。

知识库发布快照包含文档版本集合及所用索引版本。文档替换先追加版本并重建索引，通过检索测试后形成新知识发布；专家草稿可选择升级，再发布新的专家版本。不得因后台替换文档而静默改变旧专家会话的知识依据。

新会话默认使用当前专家版本；旧会话保持已绑定版本。账号停用、专家下架或资料撤权等当前授权变化优先于版本固定。Embedding 配置退出服务前需为仍被使用的索引提供兼容查询或迁移方案；无法继续时明确提示，不跨模型混查。

预览使用正式检索与对话底座，绑定一次确定的草稿及依赖快照，仅超管可进入。编辑中另一次修改不改变已启动的预览；再次测试创建新快照。超管能看到改写问题、候选与最终片段、出处、工具、耗时和用量，不展示隐藏模型思维链。预览不是免费或绕过权限的运行入口。

发布前检查：必填字段、已就绪的知识发布、有效技能包、可用工具配置、模型能力匹配和检索模式。无法访问的依赖必须阻止发布或要求明确改为不依赖该能力的配置。

## 12. 工具和方法技能

V1 保留现有搜索、网页读取、表格分析等内置云端工具，统一注册和服务端授权校验。SKILL.md 继续按需加载，提供方法说明，不以关联技能自动授予工具。

V1.1 新增 OpenAPI 工具管理：导入 schema，选择允许的具体 operation，超管登记凭证并执行测试，再关联给专家。首批支持无鉴权、API Key、Bearer 和 Basic；OAuth 需要独立的连接与授权流程后再增加。凭证不进入模型输入、公开目录或客户端。

外部工具按操作区分只读和写入；写入动作需遵守既有用户确认机制，测试环境也不能绕过。限制目标地址、超时、响应体和每轮调用数量，校验参数与返回格式；记录工具版本、调用结果及真实产物，不把自然语言“已完成”当作执行成功。

## 13. 数据结构和接口建议

新增或扩展的逻辑实体：KnowledgeBase、KnowledgeRelease、KnowledgeDocument、DocumentRevision、IndexRevision、KnowledgeChunk、ChunkEmbedding、IngestionJob、ExpertKnowledgeBinding、RetrievalRun/Hit、ToolDefinition/Revision、CredentialReference。现有 OfficialAgent/Version 和 OfficialSkill/Package 保留并扩展关联。

资料版本与索引版本独立：同一原文件可以用不同切块或向量模型生成多份索引；一份索引发布后不被原位覆盖。基于租户、库、发布版本和文档版本建立过滤索引。Embedding 配置限定维度并使用与它匹配的向量列或分区，工程计划需给出数据库迁移细节。

建议接口组：超管知识库 CRUD；上传/处理任务/取消/重试；原文与 chunk 预览；检索测试；知识发布；专家草稿/预览/发布/回退；会话检索；带权限的引用打开。第一期新接口明确归属统一知识服务，旧接口通过适配器读取。

会话检索请求由可信宿主提供专家版本、会话/轮次标识、问题和必要的有界上下文；服务端从身份中取得账号与租户，并计算资料范围。返回 retrievalId、状态、重建后的查询、来源片段、版本与定位、裁剪/降级说明和耗时。调试详情只向超管开放，用户只看到可理解的来源与状态。

缓存至少绑定账号/权限范围版本、专家版本、知识发布、文档及索引版本、Embedding 配置、查询和必要上下文哈希。命中缓存仍需重新授权；不在不同企业间共享正文检索缓存。内容、模型或权限变化使对应缓存失效。

## 14. 成本、监控与失败处理

分开计量文档解析/向量化、查询向量化、重排、对话生成及工具调用。知识入库成本记平台运营；用户使用按现有计费规则扩展，明确预览归属且不重复计费。供应商返回 usage 时保存原始计量；没有真实计量时标记估算，不伪称实付。

记录每个阶段耗时、队列积压、失败率、候选数量、命中来源、上下文 token 数、模型与索引版本及成本。日常日志不默认保存客户完整问题和正文；排障详情限定权限和保存期限。结果中的来源正文仍按会话可重建要求持久化保护。

Embedding 不可用时不将文档标为可用；查询失败不显示“没有相关资料”。如启用关键词降级，回答和后台均说明降级。Worker 中断、发布切换、跨账号切换、检索取消及权限变更均需防止旧结果进入下一轮或另一个会话。

## 15. 验收体系

先为文案、资料答疑、联网调研三个专家完成真实端到端验证，再扩大到其余专家。文本 RAG 首先建立 60 题固定评测集：直接事实 15、同义改写 15、连续追问 10、跨片段/对比 10、资料无答案 10；另设权限、删除/撤权、文件替换、索引切换和取消等工程用例。

以下为建议验收目标，不是已取得结果：

| 指标 | 建议门槛 |
|---|---|
| 有答案的 50 题中，前 5 个最终检索证据命中至少一个标注证据的比例 | 至少 90%；跨片段题另检查所需证据覆盖，不用单个命中冒充完整回答 |
| 回答中的引用定位和版本正确 | 至少 95%，并人工核对是否支持结论 |
| 无答案题准确说明依据不足 | 至少 90% |
| 已定义越权用例返回其它用户/企业资料 | 0 次 |
| 版本、撤权与取消用例 | 全部通过 |
| 检索延迟 | 在约定语料量和并发下，以 p95 约 3 秒为初始目标；先实测，不作未经验证的生产承诺 |

必须增加的案例：答案在长文档末尾；中文同义词；编号和日期；一个知识库多个文档；两份文档规则冲突；表格跨块；扫描件；不支持格式；部分解析；第一次模型请求确实包含证据；切换专家后旧召回不被沿用；引用打开时再次授权；新索引候选不足；上游模型及重排超时；无证据不生成完成声明。

分别评估解析覆盖率、证据召回、排序、回答正确性和引用忠实性。检索命中不等于回答正确，答案看起来正确也不等于成功使用了知识库。

## 17. 兼容与迁移

当前存在官方专家库、旧企业知识库和新企业资料库三条路径。通过来源适配器建立统一文档和版本引用，保留旧 ID 映射、现有企业 ACL 和已发布专家。已有纯关键词或字符哈希索引仅作为旧基线，不直接宣称是新语义索引。

先只读盘点和备份，再在影子索引中导入和评测；原文件无法核对、解析失败或缺失依赖的项列为待处理，不批量补造完成状态。初始化只创建缺失资产；再次执行不覆盖管理员草稿，也不自动发布。

按专家逐个启用新检索，保留旧读路径和路由开关。版本、召回或费用回归时回切旧路径，并保留新索引用于排查。线上迁移、删除旧数据和正式部署另行按已授权发布流程执行；本方案不执行这些动作。
