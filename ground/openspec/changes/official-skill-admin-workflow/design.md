# design

## 放哪

- 管理端：`ground/apps/frontend` 技能页、发现弹窗、图片校验。
- 接口：`ground/apps/backend` 官方技能服务与 ZIP 解析。不新增 Prisma 列，不写迁移。
- 终端：`mammoth-agent` 广场详情与任务标签。绑定仍走现有 `createSkill`，不新增会话类型。

## 字段契约

| 字段 | 存储 | 保存 | 启用 | 说明 |
|---|---|---|---|---|
| 标识 `key` | `official_skill.key` | 新建手填由服务生成；ZIP 有合法 key 时沿用，冲突则拒绝创建；无 key 时生成并标记派生 | 必须已有 | 编辑只读。规则仍是 `^[a-z][a-z0-9-]{1,63}$`，管理员不手填 |
| 名称 `name` | `name` | 必填，≤40 | 必填 | 展示名，可中文 |
| 一句话介绍 `summary` | `summary` | 可空，≤140 | 必填 | 原「用途」 |
| 分类 `category` | `category` | 可空，沿用现有枚举 | 不要求 | |
| 技能指令 | 当前包 `SKILL.md` | 手填可空则不建包；已有包不允许把正文存成空串 | 必须有非空正文且包就绪 | ZIP 的正文来自包，不要求再手填 |
| 图片 | `customAvatarPath` | 可空 | 不要求 | 入库前转 PNG |
| 详细介绍 / 示例 / 更多说明 | `discoveryDetail` | 介绍可空；示例最多 3 条且只存 `{text}`；产出、资料、边界各最多 5 条 | 不要求 | 与包正文分开 |
| 来源 | `sourceName` / `sourceSummary` / manifest `license` `source` | 已有值不被展示名覆盖 | 不要求 | 新包只在来源为空时回填 |
| 启停 | `enabledAt` | 保存不改启停 | 成功才写入时间 | 停用只清空 `enabledAt` |

创建方式只出现在新建。编辑按内容来源显示：ZIP 技能替换包，手填技能改指令。

## 状态规则

- 普通保存：只校验名称，以及「这次确实提交了的 ZIP 必须先解析成功」。允许没有介绍、分类、图片、指令或包。
- 保存并启用：先按普通保存写入可保存草稿，再启用。缺介绍或指令时草稿留下，`enabledAt` 仍为空。已有介绍或指令不会被这次的空白覆盖。已启用技能若会被改成残缺，则整次不写。发现弹窗同样先保存介绍；启用失败时介绍保留、技能保持停用。
- 新建和替换 ZIP 在数据库事务里对技能行 `FOR UPDATE` 之后才分配版本并写盘。解析失败、版本戳不一致或库写入失败都不会切换当前包；失败时删掉这次的新目录。
- 已启用技能再保存：合并后的结果必须仍完整，否则整次拒绝，不改数据和启停。已启用不再次调用启用。
- 停用：前台不再给新会话；不删技能、包、历史会话。
- 三入口字段：编辑弹窗只改名称、介绍、分类、指令或包、图标；技能介绍只改 `discoveryDetail`。未出现在请求里的字段保持不动。
- 并发：编辑、替换包、图标、技能介绍都带打开时的 `updatedAt`。不一致返回 409「技能已更新，请重新打开后保存」，不写库。包文件只在校验和版本戳通过后写入；库更新失败时不切换 `currentPackageId`。

## ZIP

接受：

- 根目录 `SKILL.md`，可无 `skill.json`。名称和介绍来自 frontmatter 的简单 `name` / `description`，否则用来源目录名或首行标题。
- 恰好一个外层目录，或嵌套后仍只有一个非 `references` / `resources` 的 `SKILL.md`。
- 忽略 `__MACOSX`、`.DS_Store`、`._*`、`Thumbs.db`。

拒绝并给出对应原因：损坏、不安全路径、缺少 `SKILL.md`、多个入口、空正文、超量、不支持的附加文件。不把任意压缩包当成技能。替换时先解析；标识不一致或解析失败不写新版本。

`skill.json` 重写时保留 `license` 和 `source`。执行正文原样入库，不翻译。

## 图片

技能编辑复用专家的居中预览和「上传图片」。前后端都接受 PNG、JPEG、WebP、GIF、SVG，最大 5MB。服务端沿用现有安全 SVG 栅格化和 GIF 首帧。展示处有有效地址只渲染图片，失败或无地址才用默认图标；地址变化清掉失败状态。透明图不叠默认图标。

## 终端

详情顺序：图和名称、一句话介绍、与一句话不同的详细介绍、试试这样用、折叠的更多说明、蓝色使用技能。示例整行点击把完整问题交给现有草稿初始化（已有草稿保留），并绑定真实技能。使用技能只绑定。两者都不自动发送、不调用模型、不写入用户消息。

## 删除

确认文案是「确定删除技能「名称」？删除后不可再选用，已有对话和任务记录不受影响。」一次确认，取消不请求。

服务端确认调用者是超级管理员或平台管理员后，只写 `deletedAt` 并清空 `enabledAt`。不删技能包、专家关联、对话、任务、消息或结果。这和停用不同：停用还能再启用；已删除不能经编辑或启用接口复活。

新会话和之后的新执行走 `POST /sessions`，技能已删除时返回「技能已删除，请重新选择」。删除和这次启动对同一行 `FOR UPDATE`，避免用过期的启用状态放行。已经冻结的执行只按绑定修订号读内容和资源，不因删除中断。历史标签通过 `GET /availability` 显示「已删除」。

## 兼容

旧行没有包时可以继续保存名称。旧示例只读 `text`，只有短标签的条目不当成问题。调用方显式提交 `starters: []` 后不得用旧开场白回填。无图技能继续显示默认图标。
