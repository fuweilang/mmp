# 专家广场＋技能

## Why

猛犸已有官方智能体、发布管理和技能按需加载底座，但产品入口仍缺少统一的「专家 / 技能」选择与可维护的技能内容包。第一版要把两种入口放在同一广场，复用 Ground 单一内容源与 DSH 标准会话，不另建插件市场或旧系统适配层。

## What Changes

- 总入口「专家广场」，两 Tab「专家 / 技能」。启用状态由 Ground 决定，全部有效登录用户可见，不以企业 grant 二次筛选。
- 专家和技能均以极小卡片呈现；支持少量名称/简介搜索与单一分类栏。点击即新建会话，不修改或覆盖旧会话。
- 会话头显示当前专家或技能来源。标准模式及文件、终端、联网保持不变。
- Admin 复用官方智能体完整 CRUD 与现版发布管理，补分类、启停、关联技能与引用提示；新增技能 CRUD 和启停。
- 技能有两条超管创建入口：ZIP（简单主路径）与表单，两者生成等价受管包；受管包内含最小 manifest、指令正文与可选引用资源。Admin 不展开工具注册或沙箱声明。
- 新会话只接收技能摘要；显式选择技能时再加载技能指令，仍按需要提供引用资源。选择专家时只开放其关联的技能，不把全部技能正文塞进上下文。
- 知识库保持两条既有边界：猛犸知识库是 Admin 官方知识库，企业知识库在 Console。允许保留专家知识引用关联，不扩展页面、不做迁移。
- 第一版后台可见已上传技能包列表及覆盖/停用状态；不提供审核、评分、交易或复杂版本管理。

## Why This Order

ZIP 主路径、表单编辑和专家关联先形成 Ground 内容源。接着接入 Web / 客户端广场与新建会话，再接技能按需加载。标准会话与知识库隔离先于概念扩展，避免把一个受管技能包做成新的插件管理后台。

## Capabilities

### Affected Capabilities

- `expert-skill-gallery`：双 Tab 统一入口、全员启用目录、双端新建会话与来源回显。
- `official-expert-configuration`：现有官方智能体 CRUD 的增量配置、分类、技能和知识引用。
- `managed-skill-packages`：ZIP/表单创建、启停、包内容读取与失败收口。
- `managed-skill-sessions`：技能选择、摘要目录、显式加载和原会话冻结。

### Non-Goals

- 用户安装、卸载、上传、私有权限、审核、评分、交易和复杂版本。
- 导入旧代码、接口、权限、品牌或建立任何旧系统兼容承诺；旧系统只作人工筛选数据源。
- 公共工具注册、模型工具注册面板、插件安装器；Skill 的运行沙箱声明不属于 Admin 表单/包字段。
- 运营自动推荐、非用户/模型显式选择的包内容批量注入、多层技能编排。
- 企业知识库页面扩展、知识库迁移、把官方与企业知识库合并。
- 测试、QA、构建、浏览器验收、Git、发布和云端分支。

## Dependencies

本 change 依赖现有 Ground 官方智能体管理、登录与角色管理、官方/企业知识隔离、DSH 标准会话和 skill provider 能力。旧 change `official-agent-gallery-import` 保持原记录不改；其过期授权语义不得覆盖本 change 的「启用官方内容全员可见」。冲突时，本 change 处理专家/技能入口、技能包与新会话行为为当前依据。

实施验证由协调方另行决定，本项目阶段不执行。
