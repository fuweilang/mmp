# 跨端会话历史

本模块接收客户端和 Web Host 的新会话副本，供同一账号在同一企业内只读查看。账号归属来自服务端已验证的登录身份，企业归属来自当前登录上下文；上传正文中的账号和企业必须与之匹配。平台管理员也只能查看自己的历史，不获得跨账号读取权限。普通用户还需保留当前企业的有效成员关系。

- `POST /api/session-history/sync`：按账号、企业、设备和本地会话标识唯一定位副本，按原始消息序号去重。事务锁防止并发重试破坏数据；旧版本及已完成版本的迟到批次不再写入。最终批次必须确认消息完整后才能标记完成。
- `GET /api/session-history`：仅查询当前账号和企业，支持会话标题、项目名称搜索及分页。
- `GET /api/session-history/:id`：校验归属后分页读取用户与助手消息，无权限时返回不存在。
- `POST /api/session-history/heartbeat`：仅更新当前账号、企业和设备的最近在线时间。

仅接收用户输入、助手文本、项目名、设备来源及本地文件显示名，不接收模型思考、工具原始载荷或文件内容。文件显示名不授予访问或下载权限。项目文件同步、跨端执行及旧历史自动导入不在本模块范围内。

数据库迁移为 `20261104200000_session_history`。本地隔离、重复上传及不完整批次回滚验证：在 `apps/backend` 执行 `node --test test/session-history.integration.test.cjs`。该验证使用临时账号和企业，完成后仅清理自身测试记录。`test/session-history.fixture.cjs` 为相邻智能体仓库的集中链路验证提供临时 HTTP 服务，通过子进程 IPC 传递临时凭证。
