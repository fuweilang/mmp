# 浏览器控制台登录衔接

`POST /api/auth/browser-sso-consume` 验证单次登录票据、账号状态及目标企业后，检查浏览器现有 Cookie。只有通过 JWT 签名和有效期验证、用途为普通登录、账号及企业均与目标一致时，才保留现有登录 Cookie，避免打开控制台新标签后使智能体 Web 页已验证的凭证失效。

登录页兑换票据前只清理本地身份缓存，不调用服务端退出登录接口，避免提前清除其他标签页共用的有效 Cookie。

没有现有 Cookie、Cookie 无效或过期、用途不符、账号或企业不同，都会签发目标身份的新 Cookie。保留原 Cookie 不延长原有登录有效期；票据仍然单次使用，不改变登录、切换企业及退出登录的行为。

回归验证：在 `apps/backend` 执行 `node --test test/browser-sso-session.test.cjs`。验证运行实际 `Login.vue` 的初始化流程、Pinia 账号 Store 和 HTTP 客户端，并使用临时账号、企业和角色，覆盖企业控制台、管理端、相同身份保留凭证、不同身份替换凭证及票据重放拒绝，并仅清理自身测试记录。
