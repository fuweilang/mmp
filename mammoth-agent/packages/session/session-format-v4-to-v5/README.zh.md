# Session V4 到 V5

[English](README.md) | 中文

## 概要

此相邻版本库只升级头部版本。旧 V4 读取方在读取或修复内容之前拒绝 V5。[格式权威文档](../../../docs/session-format-status.zh.md)区分当前写入方、已接受版本和已发布版本。

## 转换与校验

| 数据 | V4→V5 规则 |
|---|---|
| 头部 | 要求保留的 V4 逻辑字段，将 `version` 从 4 改为 5，其余字段不变。 |
| 所有接受的事件 | 保留 type、seq、time、id、负载、表面位置、来源事件引用及顺序；不删除或插入事件。 |
| 消息 | 保留角色、内容、id、来源 kind（包括旧标题拼写）、可选引用及不透明元数据；请求文本不变。 |
| 继承 | 保留精确逻辑截点；未知截点由最后一个 inherited end-seed 标记确定。拒绝矛盾或缺失的标记。 |
| 插件及未知事件 | 保留未知可忽略记录的原名。按捕获的 V4 事件集合拒绝未知必需来源名称；该集合包含[迁出归档](../../../docs/persistence-changes/historical-formats/v4.zh.md)中的本地 RAG 记录。 |
| 投递坐标 | 保留旧代值和 seq 引用。验证 V4 来源所有权，拒绝来源标记声称目标 V5；原生 V5 仅验证当前 V5 投递所有权。 |

来源解码复用未修改的已发布 V4 编解码器。各个独立 Stage 原样发出事件并将其引用保留到 EOF，以验证完整的 V4 关系。紧凑运行通过迭代处理，不生成中间展开数组。本边没有外部前置数据；更早的 V3→V4 转换仍需要子会话证据。严格目录恢复还在发布前应用已安装的当前 Session 校验。

原生 V5 编码将未变的行和消息规则交给保留的 V4 编解码器。原生 V5 元数据使用相同字段及版本 5。V5 恢复器为保留的 V4 关系校验器提供仅用于校验的头部/投递视图，然后返回原始工件，不改动事件。当前 JSONL 扫描器丢弃可恢复后缀之前就会拒绝未知必需物理行，包括压缩输入。未知可忽略负载保留既有的不解释行为。

只读打开在内存准备转换，不发布。写入打开使用既有的已验证后继发布流程，然后才追加；前代的路径、字节及 inode 不变。选中最高代后，V5 被拒绝或损坏都不会回退到 V4。目录为历史子会话发现提供固定的 V4 前置读取方。

## 模型体验

### 恢复的请求

#### 模型看到的内容

原始记录的消息、`source.kind` 和 `TextBlock.reference` 值保持不变；本库不添加面向模型的输入。

#### Token 影响

转换不改变请求文本或承载 token 的数据。

#### KV Cache 影响

转换保留记录的请求前缀。供应商缓存可用性及淘汰由外部管理。

## 已知限制与后续工作

- **历史校验** — 超出捕获来源名称或保留 V4 内容规则的历史表示会失败，不改变来源，也不发布后继。来源关系校验将事件引用保留到 EOF。格式归档记录 schema 检查点，不代表所有同版本表示或发布证明。真实供应商质量及生产验收不属于本库。
