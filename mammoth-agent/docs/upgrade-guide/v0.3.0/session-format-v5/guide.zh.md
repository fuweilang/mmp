# 将 Session 存储升级到 V5

## 变更

Session 写入格式从 4 升级到 5，使旧读取方在任何尾部恢复之前通过头部拒绝新必需专家证据。应用及 SQLite 版本不变。只读打开可在内存准备旧历史；写入打开先发布已验证的 `session.v5.jsonl` 或 `session.v5.jsonl.zstd`，再追加事件。已有代保留路径和字节。详见[兼容性确认](../../../persistence-changes/2026-11-10-official-expert-knowledge.zh.md)。

## 迁移

1. 停止所有使用目标 Session 根目录的进程，然后将共享该目录的所有进程升级到支持 V5 的构建。
2. 正常打开已有 Session。首次写入通过相邻迁移链发布 V5，无需批量修改头部。保留所有旧文件。
3. 确认 Session 可重新打开，目录中的前代文件旁出现按版本命名的 V5 后继。如果不支持的历史数据导致转换被拒绝，保留原文件并报告诊断；不会发布不完整后继。
4. 此后使用支持 V5 的读取方。存在 V5 时旧读取方不会回退到 V4；编辑或删除新代不是受支持的降级方式。
