## 缺陷

### F1c（P2，本轮新增代码内未处理）`sms/send` 冷却响应可枚举注册状态
- `ground/apps/backend/src/auth/sms.ts:199-202`（不可下发 → 固定 `retryAfterSeconds: 60`）vs `:204-215`（已注册且 60s 内发过 → **真实剩余秒数**，dev 还带 `mockCode`）
- 实测（真实 HTTP）：未注册 `{"ok":true,"retryAfterSeconds":60}`；已注册 + 35s 前的活码 `{"ok":true,"retryAfterSeconds":25,"mockCode":"123456"}`
- 生产影响：攻击者先对目标号发一次码（受害者收到 1 条真短信），立即重发即可由「<60 的剩余值」判定号码已注册；`GET /api/auth/sms/send` 是匿名接口
- 修法：冷却分支同样返回固定 `COOLDOWN_SECONDS`（前端 `Login.vue:169` 用该值倒计时，回 60 只是更保守），或返回 60 的整数倍分桶。`mockCode` 仅 dev 出现，可不动

### F1b（P3，残留侧信道）`sms-login` 耗时区分号码状态
- `auth.service.ts:269`（先查 user）→ 命中的 active 号多走 `findLatest`+`bumpAttempts`；`auth.service.ts:273` 的不存在/停用直接返回
- 隔离 PG 实测中位数（100 次）：未注册 0.89ms、停用 0.40ms、已注册无活码 1.64ms、已注册错码 1.80ms；换轮次复测 active 仍为 unknown 的 1.8~2.1 倍，HTTP 网络抖动会削弱但同机房可统计
- 修法：不存在/停用号也执行一次等价的 `findLatest` + 空写（或先 `consume` 再查 user），成本换等时；`attempts` 自增本身也是可被库侧观测的差异

### F1d（P2，既有，非本次范围）密码登录时间差可枚举账号
- `auth.service.ts:283-289`：仅用户存在且 active 才跑 `bcrypt.compare`
- 实测中位数：未注册 1.3ms、停用 1.3ms、已注册错密码 **61.7ms**（`/api/auth/login`、`/api/auth/client-login` 共用 `openSession`）
- 修法：用户不存在/停用时对固定 dummy hash 跑一次 `bcrypt.compare` 再抛同一错误

### F2'（P1，既有，非本次改动，需安全裁决）OIDC 回调开放重定向 → 7 天会话 JWT
- `ground/apps/backend/src/oidc/oidc.service.ts:114-136`：`isAllowedRedirect` 命中 `/api/auth/oidc/callback`、`/agent/api/auth/oidc/callback` 时**只校验 pathname 不校验 host**；实测 `https://evil.example/api/auth/oidc/callback` → `true`
- 链条：攻击者构造 `/oidc/authorize?...&redirect_uri=https://evil.example/api/auth/oidc/callback&code_challenge=<攻击者PKCE>` → 受害者点链并按 `next` 登录 → code 被 302 到攻击者域 → `POST /oidc/token` 换到 `console_handoff_token`（`oidc.service.ts:220-223`，`{sub,tenantId}` 7 天，等价 ADMIN 会话）
- 非匿名（需受害者已登录/登录一次），且该文件本轮未改；`oidc/token` 本身匿名拿不到 code（随机 code → 401）
- 修法：这两个 pathname 同时要求 host ∈ `PUBLIC_ORIGIN` 白名单（`www.mmai.vip` / 127.0.0.1 loopback），或直接要求 `redirect_uri` origin === `publicOrigin()`
