# 企业共享目录与权限继承

用户已批准：共享入口新建默认为企业可见；共享目录的新建、上传、链接继承范围；共享已有目录递归覆盖所有子项。普通成员可创建，所有者保留归属；企业全员可读，不增加他人编辑权限。只实施本地代码，不部署、不提交或推送。

采用创建时保存 scope，并在目录共享时原子更新整棵子树；不采用每次读取递归计算权限，避免同时重写预览、问答、下载等鉴权。复用 LibraryNode 的现有字段，无历史资料自动回填。

根目录接收显式 scope 和共享确认；有父目录时以服务端目录范围为准，前端在操作前展示范围。共享创建不得以先私有、再共享的两次请求实现。上传捕获目标及范围，提交重新验证，目录变化返回冲突并清理新 blob。

目录共享先校验全部待变更子项 canManage，不能共享他人私有资料；一项失败整次失败，错误不泄露隐藏标题。递归包含回收中的未彻删资料，防止恢复后破坏范围；彻删项跳过。所有权及 ID 不变。共享目录内不能单独取消共享；先移出。目录取消共享需要显式确认全部子项影响并逐项管理授权。私有资料/目录移入共享目录须确认并递归共享；共享资料移出保留共享范围。

同一租户的目录树写操作串行事务，覆盖创建、移动、范围变更和回收/恢复，防止新增子项与递归共享交错。彻底删除保持原有流程；物理文件删除不能随数据库事务回滚。平台代管仍需原范围与目标范围授权，不能借继承扩大代管能力。

Console 和桌面端携带相同目标参数，创建成功留在原目录；范围提示和递归影响数量来自服务端。个人根目录仍私有。旧客户端共享目录上传也执行后端继承规则。

验收覆盖根目录共享、任意层级继承、递归历史资料、无权子项整次拒绝、原子回滚、并发创建/共享、移动确认、取消共享、跨租户、离职成员、平台代管、个人私有与两端用户操作。
